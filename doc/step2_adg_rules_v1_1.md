● 《第 2 步页面展示与 ADG 预检查规则 v1.1 最终冻结稿》

  ---
  零、总则（新增）

  0.1 展示字段原始证据规则

  - 所有展示字段不直接显示原始 evidence 内容
  - evidence 仅用于后端验证和生成结论
  - 前端只展示最终值、标签、检查结论
  - 如需查看详细证据，通过"展开详情"按钮展示，且仅限调试模式或管理员

  0.2 字段来源唯一性规则

  - 同一字段只能有一个最终来源
  - 不允许"同时是用户输入又是自动探测"的模糊状态
  - 后端必须明确：先检查用户输入 → 用户输入则忽略自动探测 → 无用户输入则使用自动探测

  0.3 网络连通性检查模型

  - 双向检查模型：从管理节点（运行预检查的主机）分别测试到主库和备库的连通性
  - 检查内容：
    a. SSH 端口互通（22 端口可达）
    b. 监听端口互通（主库监听端口可从备库访问，反之亦然）
  - 不区分：不做"主到备"和"备到主"的区分，统一为"管理节点到各目标"

  1.2 标签使用约束（不变）

  1. 禁止出现"未探测到" - 这是无语义的泛标签，必须替换为上述明确标签之一
  2. 禁止"有值但来源不明"字段误标"用户输入" - 只有第 1 步用户真实输入的才能用此标签
  3. 每个展示字段必须对应唯一标签 - 不得同时使用多个标签

  备库 Oracle 版本来源规则收紧：
  - 优先顺序：安装环境探测（sqlplus -v）→ 继承主库
  - 不探测备库实例：不通过 v$version 或 v$database 查询
  - 安装环境探测失败：直接继承主库版本，标注"继承主库"

  备库 SERVICE_NAME 计划值规则收紧：
  - 用户未输入时：默认值 = 备库 DB_UNIQUE_NAME
  - 不尝试探测：不通过 v$parameter 查询 service_names
  - 标签：始终为"计划值"

  约束说明：
  - 备库字段来源只能是：用户输入、继承主库、计划值、安装环境探测值
  - 严禁对 standby 执行依赖实例已启动的 SQL 查询
  - 严禁把 SQL 原文或探测失败的 SQL 语句返回给前端

  八、最终建议

  8.1 第一批实施规则（优先级高）

  1. 标签体系实施：优先实现，这是展示的基础
    - 前端：添加标签组件（Badge 样式）
    - 后端：确保所有返回值带有来源标识
  2. 展示字段原始证据规则：高优先级
    - 前端：确保字段不直接显示原始 evidence
    - 后端：evidence 仅用于验证，不作为展示值
  3. 字段来源唯一性规则：高优先级
    - 后端：实现用户输入 → 自动探测的明确优先级
    - 确保同一字段只有一个最终来源
  4. 主库字段来源规则：中等优先级
    - 后端：添加用户输入值的一致性校验逻辑
    - 前端：根据用户是否有输入决定展示内容
  5. 备库字段来源规则：高优先级（当前有 SQL 泄漏风险）
    - 后端：确保备库字段只使用允许的来源
    - 严禁返回 SQL 原文
    - 收紧 Oracle 版本和 SERVICE_NAME 的来源规则

  8.2 第二批补强规则（后续迭代）

  1. 删除/替换旧检查项：低优先级
    - 后端：修改检查项名称和分组
    - 前端：调整展示方式
  2. 补充的前置检查项：中优先级
    - 版本一致性、NTP、防火墙等
  3. 预检查结果详情展开：中优先级
    - 优化长文本 evidence 的展示方式
    - 添加"展开详情"功能（调试模式/管理员）
  4. 目录空间阈值动态配置：低优先级
    - 允许管理员配置空间警告/失败阈值
    - 当前固定为 85%/95%

  8.3 实施建议

  1. 前后端并行开发：标签体系和字段来源规则可以前后端并行实现
  2. 向后兼容：保留现有的预检查项 ID，仅优化展示方式和分组
  3. 渐进式替换：删除/替换的旧检查项可以先标记 deprecated，后续版本再移除
  4. 测试重点：
    - 备库未创建场景下的字段来源
    - 用户输入与自动探测的切换逻辑
    - evidence 不直接展示的验证
